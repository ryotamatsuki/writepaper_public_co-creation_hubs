# Stage 3R Mechanism Candidates

All candidates are constrained to P1 local linkage state `L`, P2 external linkage state `X`, and P3 portfolio decision scope `S`. No additional economic primitive is authorized.

## M-A — Scope-Constrained Composition
A bounded unit can select only architecture components inside its assigned portfolio, while an integrated benchmark can compare all 0/H/P/HP alternatives.

**Appeal:** fits observed bounded programs.

**Fatal test:** if misselection occurs because an alternative is literally unavailable, the result is a choice-set tautology. Multidimensional regional state is not essential.

**Verdict:** KILL.

## M-B — Modular Duplication / Omission
Separate bounded modules may collectively omit H/P or commission an unnecessary combination.

**Appeal:** can generate under- and over-composition.

**Fatal test:** with common objectives and no cross-module payoff/resource externality, independent component decisions reproduce the integrated component choice. To obtain duplication/omission one must add noninternalized returns, shared resources, objective differences or coordination costs.

**Verdict:** KILL — generic coordination / missing primitive.

## M-C — Sequential Scope Dependence
An initial bounded decision changes a later H/P module choice.

**Appeal:** relates to OIH GLOBAL BRIDGE and Saga Connect+ additions.

**Fatal test:** Stage 2R establishes modular addition, not endogenous path dependence. To make timing consequential requires irreversibility, learning, state transition or sunk investment, none of which is authorized. Without that, sequencing is removable.

**Verdict:** KILL.

## M-D — Portfolio-Level Substitution Neglect
A task-specific unit evaluates its own H or P module against no action, while an integrated chooser compares composition across H/P alternatives.

**Appeal:** potentially yields wrong composition rather than only underprovision.

**Fatal test:** the mechanism requires H and P to be economic substitutes or to share an opportunity/resource constraint. That cross-task relation is not P1/P2/P3; it is a new primitive. If substitution is simply asserted, the desired result is built in.

**Verdict:** KILL — unauthorized cross-task primitive.

## M-E — Distributed Architecture Aggregation
Several bounded decisions are individually rational but aggregate to the wrong regional architecture.

**Appeal:** reflects the rejected prefecture-year union as a real distributed system rather than a unitary actor.

**Fatal test:** inefficiency requires each unit not to internalize some effect of the other units, or different objectives/information. That is generic public-good/coordination/fragmented-government economics and adds a wedge not in the frozen primitives.

**Verdict:** KILL.

## M-F — Scope-State Mismatch
A bounded task scope aligns with only part of the two-dimensional regional state, so the decision process fails to choose the architecture that would be selected under integrated consideration of `(L,X)`.

**Appeal:** strongest apparent joint use of P1/P2 and P3; fits same-principal task-specific menus and modular external programs.

**Fatal test:** there are only two ways to make it work. (1) The bounded unit is denied the alternative action/state dimension, in which case misselection is imposed by the action/information restriction and survives even with one state dimension. (2) The unit has the same information and objectives but H/P values interact across L/X, in which case a new cross-task payoff primitive has been introduced. Thus the desired bottom-right two-by-two interaction is not generated by P1/P2/P3 alone.

**Verdict:** KILL — strongest candidate, but fails primitive sufficiency.

## Mechanism ranking before fatal kill
1. M-F Scope-State Mismatch
2. M-D Portfolio-Level Substitution Neglect
3. M-C Sequential Scope Dependence
4. M-B Modular Duplication / Omission
5. M-A Scope-Constrained Composition
6. M-E Distributed Architecture Aggregation

No candidate survives to Stage 4R.
