# Stage 0R Architecture Classification

## Unit of analysis

The primary architecture unit is a region-year public intermediation system, not a building label. Facility-level coding is used only as a pilot source. This distinction is necessary for the `0` regime because a region can lack a named hub while still receiving H or P from universities, chambers, banks, digital programs, or private intermediaries.

## Functional coding

### H — local intermediation
Code `H=1` only when an official source documents at least one dedicated function that reduces within-region search/coordination frictions: local partner discovery, local matching, brokerage, project formation, community management, or local knowledge translation.

### P — extra-regional connectivity
Code `P=1` only when an official source explicitly documents geographic reach beyond the target region: outside-region partner search, national/global matching, external expert/investor recruitment, overseas support, or systematic resource import from another region. Generic openness or an undifferentiated partner list is not enough.

### Architecture
- `0`: H=0, P=0 after accounting for public and material private/existing intermediary alternatives.
- `H`: H=1, P=0.
- `P`: H=0, P=1.
- `HP`: H=1, P=1.
- `UNCERTAIN`: evidence is insufficient to separate functions.

## Pilot implications

The 18 screened facility/program cases produce clear positive-regime variation. Provisional distribution: H-heavy cases are common; HP is observed in both metropolitan and smaller prefectural systems; NEXs Tokyo provides a clean P-dominant example. This alone kills the legacy technological assumption that P requires H.

The pilot deliberately does **not** report a `0` facility because inclusion criteria select organizations that provide intermediation. A valid `0` must be constructed at the region-year level by inventorying existing public, university, chamber/bank, digital, and private alternatives. Stage 1R must therefore build a denominator before estimating an architecture distribution.

## Classification hierarchy

1. Primary source describing actual services.
2. Formal program/contract specification.
3. Official annual report or evaluation.
4. Official press release.
5. Secondary source only as a locator, never as final coding evidence.

## Anti-circularity rule

Outcomes must never define H or P. A successful local collaboration does not make a facility H; an overseas success does not make it P. Architecture is coded from offered intermediation functions and decision rules.

## Complementarity discipline

`HP` means co-provision, not complementarity. Whether H and P are complements, substitutes, or independent remains an empirical/theoretical question. Shared staff, budget crowding, sequencing, participant overlap, and separate program modules must be recorded before any complementarity primitive is introduced.
