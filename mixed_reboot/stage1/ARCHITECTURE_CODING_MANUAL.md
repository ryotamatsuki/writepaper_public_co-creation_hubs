# Stage 1R Architecture Coding Manual

## Unit under test

Stage 1R tests the Stage 0R contract that the architecture choice can be coded at the **prefecture-year intermediation-system** level.

For a prefecture-year, all material publicly supported innovation-intermediation modules are unioned before coding. University, chamber/bank, private and national/digital substitutes are inventoried separately for the `0` test.

The status is measured at year-end for 2024–2026.

## Functional components

### H — local intermediation

Code `H=1` only when primary evidence documents recurrent local search/coordination activity. Qualifying functions include local matching, brokerage, project formation, sustained mentoring tied to partner formation, or local ecosystem coordination. A room, event venue, subsidy counter, or one-off seminar does not qualify by itself.

### P — extra-regional connectivity

Code `P=1` only when primary evidence documents a dedicated recurrent extra-regional function: outside-prefecture partner search/matching, systematic external expert/investor recruitment, national/global network brokerage, overseas expansion/intermediation, or recurring import of outside resources. Generic openness, a guest speaker, or an undifferentiated partner list is insufficient.

### Regimes

- `0`: H=0 and P=0 after a documented system inventory.
- `H`: H=1, P=0.
- `P`: H=0, P=1.
- `HP`: H=1, P=1.
- `UNCERTAIN`: evidence is insufficient to adjudicate at least one component.

`HP` means co-provision only; it does not imply complementarity.

## Double-pass rule

Pass A codes from explicit recurrent functions and records uncertainty rather than inferring. Pass B independently re-reads the same primary evidence using the same thresholds but a stricter presumption against P. Disagreements are retained and adjudicated rather than forced.

Because both passes are AI-assisted within one research execution, agreement statistics are diagnostic and **not** presented as human inter-rater reliability.

## Anti-circularity

Outcomes, participant success, patent counts, startup growth and later collaboration are never used to define H or P.

## Critical aggregation test

A facility/program may be `P` while the prefecture-year union is `HP`. This is not a coding error. It is the central Stage 1R test of whether prefecture-year is a useful architecture-choice unit.

## 0 discipline

`0` cannot be inferred from failure to find a named hub. Candidate `0` prefectures require an explicit search of public startup support, innovation platforms, public research/industry intermediaries, universities/TTOs, chambers/banks and material private/national substitutes.
