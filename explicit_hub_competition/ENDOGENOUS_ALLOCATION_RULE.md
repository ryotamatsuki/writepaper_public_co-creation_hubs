# Endogenous Allocation Rule

## Candidate comparison

### A1 — Expected productive-match value

**SELECTED.** A beneficiary firm-project chooses among open hubs according to the expected productive value obtainable from the hub's partner pool.

Conceptually:

`i*(theta) in argmax_i V_i(theta)`.

Differences in `V_i(theta)` must come from partner-set composition and productive compatibility, not from arbitrary hub-specific utility constants.

### A2 — Expected value minus intermediation friction

Not needed in the baseline. Search/information/coordination frictions remain legitimate microfoundations of matching, but adding a separate project-specific hub cost is unnecessary if D1 creates endogenous allocation.

### A3 — Probabilistic discrete choice

Rejected. Logit noise would create smooth shares but would not explain economically why hubs differ.

### A4 — Random tie-breaking

Permitted only for genuine measure-zero/symmetric ties. It cannot be the source of coexistence or the primary market-share mechanism.

## Referral timing

Project choice is ex ante, before exact partner compatibility is fully learned. The selected hub searches its pool. If no productive direct match is realized and the rival hub is open, a cross-hub referral may expose the project to the rival's non-overlapping partner pool.

This makes referral economically distinct from initial direct hub choice: it is a second-route matching opportunity after unsuccessful first-hub intermediation, not a generic utility bonus.

## Information discipline

The project may know its own need `theta` and the broad specialization of each hub, while partner-specific compatibility is learned through intermediation. This uncertainty is part of productive matching and does not create a new canonical primitive.
