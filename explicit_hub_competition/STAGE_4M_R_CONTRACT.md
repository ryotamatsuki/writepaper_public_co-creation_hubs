# Stage 4M-R Contract — Explicit Hub Competition Minimal Model Hard Kill

## Entry condition

Stage 3M-R verdict: **PASS — EXPLICIT HUB COMPETITION HAS A COHERENT MINIMAL MATCHING ARCHITECTURE.**

## Frozen architecture

The next stage may choose only the simplest functional forms needed to solve the following architecture. It may not change the architecture because a theorem fails.

1. Two regional governments choose binary public hub provision.
2. Each region has a beneficiary firm with a collaboration project; the firm does not relocate.
3. Hub `i` is anchored to a heterogeneous complementary partner pool `S_i`.
4. Project needs/types differ and productive value depends on project-partner fit.
5. When both hubs are feasible, the project chooses the hub with the higher expected direct productive-match value.
6. Partner-specific compatibility is learned through intermediation.
7. If first-hub direct matching fails, referral to the rival hub's non-overlapping partner pool is the only cooperative routing channel.
8. Productive collaboration creates beneficiary-firm capability gain plus complementary-partner surplus.
9. Beneficiary-firm gains remain in the firm's home region; partner-side surplus remains in the partner's region.
10. Successful matching may change downstream competitive capability; downstream firms then strategically interact.
11. Governments maximize regional welfare and pay public hub cost; hubs do not charge private fees.

## Stage 4M-R authorized formalization choices

The next stage may:

- replace `S_i` by the smallest finite partner/type representation that preserves overlap, exclusive specialization and endogenous project choice;
- choose the smallest compatibility uncertainty required to make referral distinct from initial choice;
- normalize/derive partner-side collaboration surplus transparently;
- choose the simplest downstream strategic game consistent with the frozen research question;
- derive all four hub profiles and all project-allocation states.

## Prohibited changes

Do not add:

- Hotelling distance;
- logit demand/taste shocks;
- private hub pricing;
- multihoming;
- congestion/capacity;
- continuous hub quality;
- R&D spillovers;
- absorptive capacity;
- generic network externalities;
- new cross-hub positive or negative terms;
- firm relocation;
- subsidies/taxes;
- bargaining;
- dynamics.

## Mandatory hard-kill questions

1. Does literal project competition alone push hubs toward substitution?
2. Can cross-hub referral offset literal project stealing?
3. Can the public-hub strategic cross effect take both signs on nonempty interior open sets?
4. Does explicit project allocation materially alter the diagnostic Stage 4M theorem?
5. Does downstream rivalry amplify or dampen hub competition/referral incentives?
6. Does split regional incidence create a decentralized-policy wedge absent under a planner?
7. Is any result a one-page specialization of Damiano–Li/Caillaud–Jullien plus a public-input/location model?
8. If partner-side regional surplus is deleted, does hub market share become cosmetic? If yes, record that as a mechanism-necessity result.
9. If referral is deleted, is the competition result still nontrivial?
10. If downstream rivalry is deleted, which propositions survive?

## Kill conditions

Return NO-GO if:

- project allocation drops out of government payoffs;
- partner-side incidence is an arbitrary rent needed only to manufacture competition;
- a finite specialization reduces exactly to standard competing matchmakers with public labels;
- the public layer is equivalent to standard firm-location competition despite beneficiary firms not relocating;
- desired results require an unauthorized feature.
