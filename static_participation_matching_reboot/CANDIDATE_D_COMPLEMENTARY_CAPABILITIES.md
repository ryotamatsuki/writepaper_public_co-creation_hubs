# Candidate D — Complementary Multi-Capability Matching

A project requires capabilities A and B and succeeds only when a Hub assembles both.

If capabilities are abundant/independent, expected success becomes

`mu_h(k)=Pr(A found and B found)`

and project payoff is simply `z mu_h(k)-c_h`. The bundle story has scalarized into a deterministic provider index: K3.

To prevent scalarization, A/B partners must be scarce, jointly allocated, or shared across project types. That introduces endogenous bundle shadow values and turns D into a multi-partner version of Candidate C. Matching with complementarities is a substantive theory area, and large-market existence can be obtained under specialized conditions, but embedding it inside the present three-strategic-player game is no longer minimal.

**Verdict: KILL — K3 in the tractable version; K10 if upgraded to a genuinely scarce complementary assignment.**
