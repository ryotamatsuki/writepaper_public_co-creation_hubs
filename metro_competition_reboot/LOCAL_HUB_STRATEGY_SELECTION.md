# Local Hub Strategy Selection

## Selected: X2 with X4 as a derived outcome

`x_i` is **screening/evaluation capacity over a regionally anchored heterogeneous partner pool**.

It is not generic service quality. Investment changes the opportunity set that can be diagnosed/evaluated for a project, and expected best productive match value is derived from that process.

### Candidate assessment

| Candidate | Verdict | Reason |
|---|---|---|
| X1 match probability `mu(x)` | REJECT AS BASELINE | too easily relabeled generic quality unless microfounded |
| X2 screening/diagnosis precision/capacity | **SELECT** | directly maps to intermediary activity and can be built from partner opportunities |
| X3 partner-pool breadth | EXTENSION | policy-relevant but turns ecosystem composition itself into a high-dimensional strategy |
| X4 expected max match value | DERIVED OUTCOME | useful summary statistic, but should not be primitive |
| X5 generic facility quality | **REJECT** | absorbed by public-facility and mixed-quality competition |

## Microfoundation contract

Let `S_i` be the local partner capability set and `Q_i(theta,x_i)` the subset/effective sample evaluated by the hub. Stage 1 must make `Q_i` explicit enough to derive `M_i` by order statistics, sampling, or screening precision. Investment cost `C_i(x_i)` is increasing and convex in the baseline.

## Empirical interpretation

Potential proxies include coordinator/specialist FTE, number of partner candidates actively assessed per case, specialist coverage, diagnostic capacity, cases handled with substantive partner search, and program expenditure tied to matchmaking activity. Generic building quality or event volume is not an acceptable proxy.
