# Matching Specificity Test

The economic primitive is compatibility between a project's technological need and the composition of partners that a hub can evaluate.

`theta` is not a taste for Hub 1 versus Hub 2. A project with low `theta` is technologically more compatible with the specialist component of `S_1`; a high-`theta` project is more compatible with `S_2`.

Investment does not add an arbitrary utility intercept. It raises the probability that the hub successfully identifies a productive partner from its ecosystem.

The common component `c` and specialist component `u` jointly determine which project types benefit from each unit of screening capability.

Matching specificity survives label stripping only if Stage 4 finds a result that depends on this type-by-ecosystem composition rather than merely on average provider quality. This is a hard gate, not an assumed contribution.
