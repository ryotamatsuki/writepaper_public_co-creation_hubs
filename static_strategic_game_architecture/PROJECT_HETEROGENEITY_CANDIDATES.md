# Project Heterogeneity Candidates

## H1 — two discrete technological types
Tractable matching states, but metro demand becomes step-like and public competition is corner-heavy. Rejected.

## H2 — one-dimensional continuous technological need
`theta in [0,1]` indexes the capability mix required by the project, not taste or geographic location. Gives smooth public-public sorting and metro demand. **Selected.**

## H3 — finite technological class + continuous project value
Economically clean and gives smooth participation, but adds a second dimension before it is proven necessary. Reserved only if Stage 4 demonstrates that the one-dimensional model cannot support a meaningful no-use region.

The selected model uses a common real coordination cost `kappa` to permit non-participation without adding an unrelated second heterogeneity dimension.
